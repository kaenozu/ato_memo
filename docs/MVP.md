# あとメモ — Android MVP

スクショした情報を忘れる前に見返す。Flutterの画面とAndroidの端末内バックエンドを使用する。広告・課金・アカウント・外部AI・タグ・フォルダは含めない。

## 合意仕様と初期値
- 画像共有（単数・複数）と画像選択。元URLが共有テキストに含まれる場合は保存。
- 自動取り込みは任意。スクショだけ／全画像を切替可能。許可後に追加された画像を取り込み、過去画像は別操作で取り込む。
- アプリ専用領域に画像をコピーしSQLiteに予約を保存。元画像は変更・削除しない。
- 初期通知は翌日20時のまとめ通知。設定で通知ON/OFF、時刻、毎日／週1回、翌日／当日を変更。個別予約は今日・明日・週末・日時指定。
- バンドルされた日本語ML KitでOCR。日付・時刻候補はユーザーが選んで確定。OCR失敗でも画像を保存できる。
- 通知から画像または対象一覧へ。完了、明日再通知、日時変更、削除。閲覧だけでは完了扱いにしない。
- 完了した画像のコピーは30日後に削除。通知に画像・OCR本文を表示しない。
- OSの通知権限・画像権限と実際の状態を設定画面に表示。自動取り込みは共有画像への全アクセスがある場合に動作する。
- 再起動、時刻／タイムゾーン変更時に予約を復元。省電力による遅延はありうる。正確なアラームアクセスは任意で設定可能。

## 構成
Flutter: 一覧・詳細・予約シート・設定。MethodChannelでAndroidを呼ぶ。
Android: SQLite保存、共有・画像選択、バックグラウンドMediaStoreジョブ、画像コピー、OCR、AlarmManagerと通知。
データはアプリ専用領域のみ。バックアップ無効。releaseにはインターネット権限を付けない。

## 実装・検証順
1. 保存モデルと通知日時計算: 日付境界、週末、週次予約の単体テスト。
2. 共有→コピー→OCR→一覧→予約: ビルドとAndroid上の入力、元画像削除後の閲覧。
3. 通知と設定: 実通知、タップ、再通知、完了、再起動後の復元。
4. 自動取り込み: アプリを閉じた状態でMediaStoreに画像追加しバックグラウンド取り込み確認。重複・OFF・スクショ以外の除外も確認。
5. UI・ドキュメント・APK: Flutterテスト、Androidテスト、静的解析、実画面と成果物確認。
